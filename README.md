# TyProxy

Легковесный, быстрый и устойчивый к сетевой цензуре туннель на Rust, маскирующий сетевой трафик под стандартную защищенную TLS 1.3 сессию.

Проект поддерживает два независимых режима маршрутизации на клиенте:

1. **SOCKS5** — локальный прокси-сервер (TCP + UDP Associate) для выборочной настройки приложений или браузера.
2. **TUN** — виртуальный L3 сетевой интерфейс, перехватывающий весь сетевой трафик операционной системы (включая DNS, системные службы и игры) и передающий его в зашифрованном виде на сервер без необходимости пользовательского разбора стека пакетов.

---

### 🚀 Возможности

* **Маскировка под TLS 1.3:** Трафик выглядит как стандартное защищенное HTTPS/TLS-соединение с заданным ALPN.
* **Режим TUN (L3 VPN):** Автоматически прописывает маршруты `0.0.0.0/1` и `128.0.0.0/1`, не ломая исходный шлюз по умолчанию и исключая прямой маршрут до сервера.
* **Режим SOCKS5:** Локальный прокси с поддержкой UDP (актуально для мессенджеров, голосовых вызовов и игр).
* **Минимум накладных расходов:** В режиме TUN сервер передает сырые IP-пакеты в виртуальный интерфейс ядра Linux, отдавая NAT и маршрутизацию встроенной подсистеме ОС.
* **Кроссплатформенность:** Поддержка Linux, Windows, macOS (ARM / Intel) и FreeBSD.

### 🛠 Сборка из исходников

Для базовой сборки требуется компилятор Rust (`cargo`, `rustup`). 

Для кросс-компиляции под другие платформы (в частности macOS и другие таргеты) дополнительно требуются **`zig`** и утилита **`cargo-zigbuild`**:

```bash
# Установка cargo-zigbuild
cargo install --locked cargo-zigbuild

# Zig устанавливается через системный пакетный менеджер (apt, brew, pacman и т.д.)
# либо скачивается с официального сайта [https://ziglang.org/download/](https://ziglang.org/download/)

```

Все готовые бинарники собираются в директорию `./dist/`:

```bash
# Текущая платформа Linux
make linux

# Windows .exe (требует mingw-w64)
make windows

# macOS Apple Silicon (требует cargo-zigbuild и zig)
make darwin

# macOS Intel (требует cargo-zigbuild и zig)
make darwin-intel

# FreeBSD
make bsd

```

### ⚙️ Конфигурация (`config.toml`)

При первом запуске бинарника конфигурационный файл генерируется автоматически:

```toml
# Режим запуска: "server", "client" или "ask" (интерактивный выбор)
mode = "ask"

[server]
bind_addr = "0.0.0.0:8888"
wallet_path = "server.wallet" # Файл хранилища ключей/токенов
tun_enabled = true
tun_name = "typroxy-srv"
tun_ip = "10.8.0.1"

[client]
server_host = "IP_ВАШЕГО_СЕРВЕРА:8888"

# Режим перехвата: "socks5" или "tun"
routing_mode = "tun"

# Параметры для routing_mode = "socks5"
socks_bind_addr = "127.0.0.1:1080"

# Параметры для routing_mode = "tun" (требуются права суперпользователя)
tun_name = "typroxy-tun"
tun_ip = "10.8.0.2"
tun_gateway = "10.8.0.1"

```

### 🖥 Настройка сервера

#### 1. Запуск

Установите в конфиге `mode = "server"` или выберите пункт при старте:

```bash
sudo ./typroxy

```

#### 2. Включение NAT для TUN режима (Linux)

Чтобы сервер выпускал приходящие пакеты в интернет, выполните от `root`:

```bash
# Включение форвардинга IPv4 в ядре
sysctl -w net.ipv4.ip_forward=1

# Включение маскарадинга (замените eth0 на ваш публичный интерфейс)
iptables -t nat -A POSTROUTING -s 10.8.0.0/24 -o eth0 -j MASQUERADE

```

---

### 💻 Настройка клиента

#### Вариант А: Режим TUN (весь трафик системы)

1. В `config.toml` задайте:
```toml
mode = "client"
routing_mode = "tun"
server_host = "IP_СЕРВЕРА:8888"

```


2. Запустите с правами администратора / root:
* **Linux / macOS:** `sudo ./typroxy`
* **Windows:** Запустите PowerShell / CMD от имени Администратора и выполните `.\typroxy.exe`



#### Вариант Б: Режим SOCKS5 (локальный прокси)

1. В `config.toml` задайте:
```toml
mode = "client"
routing_mode = "socks5"
server_host = "IP_СЕРВЕРА:8888"
socks_bind_addr = "127.0.0.1:1080"

```


2. Запустите без прав root: `./typroxy`
3. Укажите прокси `127.0.0.1:1080` (SOCKS5) в настройках браузера, Telegram или через проксификаторы.

---

### 🔒 Безопасность

* Сертификаты генерируются автоматически в памяти на лету.
* Трафик полностью инкапсулирован внутри TLS 1.3 сессии.
* Отсутствие явных сигнатур классических VPN-протоколов (OpenVPN, WireGuard) для защиты от эвристического анализа DPI.
