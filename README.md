# TyProxy

Легковесный, быстрый и устойчивый к цензуре туннель на Rust, маскирующий любой
ваш трафик под стандартную защищенную TLS 1.3 сессию.

Проект поддерживает два независимых режима маршрутизации на клиенте:

1.  SOCKS5 — локальный прокси-сервер (TCP + UDP Associate) для выборочной
    настройки приложений или браузера.
2.  TUN — виртуальный L3 сетевой интерфейс, который намертво перехватывает весь
    сетевой трафик операционной системы (включая DNS, системные службы и игры) и
    гонит его в зашифрованном виде на сервер без необходимости разбирать стек
    пакетов на лету.

🚀 Возможности

  - TLS 1.3 маскировка: Трафик выглядит как обычное защищенное
    HTTPS/TLS-соединение со своим ALPN.
  - Режим TUN (L3 VPN): Захватывает трафик всей системы. Автоматически
    прописывает маршруты 0.0.0.0/1 и 128.0.0.0/1 (не ломая шлюз по умолчанию и
    исключая маршрут до самого прокси-сервера).
  - Режим SOCKS5: Классический локальный прокси с поддержкой UDP (актуально для
    мессенджеров, войса и игр).
  - Без сложного парсинга на сервере: При работе с TUN сервер принимает сырые
    IP-пакеты и сбрасывает их в системный TUN-интерфейс ядра, отдавая NAT и
    маршрутизацию операционной системе.
  - Кроссплатформенность: Сборка под Linux, Windows, macOS (ARM/Intel) и
    FreeBSD.

🛠 Сборка из исходников

Для сборки требуется компилятор Rust (cargo, rustup).

В проекте есть готовый Makefile:

# Собрать под вашу текущую платформу Linux
make linux

# Собрать .exe для Windows (требует mingw-w64)
make windows

# Собрать под macOS Apple Silicon (требует cargo-zigbuild и zig)
make darwin

# Собрать под macOS Intel
make darwin-intel

# Собрать под FreeBSD
make bsd

Все скомпилированные релизные бинарники попадают в папку ./dist/.

⚙️ Конфигурация (config.toml)

При первом запуске бинарника файл config.toml создается автоматически:

# Режим работы бинарника: "server", "client" или "ask" (спрашивать при старте)
mode = "ask"

[server]
bind_addr = "0.0.0.0:8888"
wallet_path = "server.wallet"
tun_enabled = true
tun_name = "typroxy-srv"
tun_ip = "10.8.0.1"

[client]
server_host = "IP_ВАШЕГО_СЕРВЕРА:8888"

# Режим перехвата трафика: "socks5" или "tun"
routing_mode = "tun"

# Настройки для SOCKS5 (если routing_mode = "socks5")
socks_bind_addr = "127.0.0.1:1080"

# Настройки для TUN (если routing_mode = "tun", требуются root/admin права)
tun_name = "typroxy-tun"
tun_ip = "10.8.0.2"
tun_gateway = "10.8.0.1"

🖥 Настройка Сервера

1. Запуск

Смените в конфиге mode = "server" или выберите пункт [1] при старте:

sudo ./typroxy

2. Включение NAT для TUN режима (Linux)

Чтобы сервер выпускал приходящие через виртуальный кабель пакеты в интернет,
выполните на сервере от root (достаточно один раз):

# Включаем форвардинг пакетов на уровне ядра
sysctl -w net.ipv4.ip_forward=1

# Включаем маскарадинг (замените eth0 на ваш основной сетевой интерфейс: eth0, ens3 и т.д.)
iptables -t nat -A POSTROUTING -s 10.8.0.0/24 -o eth0 -j MASQUERADE

💻 Настройка Клиента

Вариант А: Режим TUN (Весь трафик ПК)

1.  В config.toml укажите:
    mode = "client"
    routing_mode = "tun"
    server_host = "IP_СЕРВЕРА:8888"
2.  Запустите клиент с правами администратора / root (это обязательно для
    создания сетевого адаптера и изменения таблицы маршрутов):
      - Linux / macOS: sudo ./typroxy
      - Windows: Запуск PowerShell / CMD от имени Администратора ->
        .\typroxy.exe
3.  Весь сетевой стек системы пойдет через зашифрованный туннель.

Вариант Б: Режим SOCKS5 (Локальный прокси)

1.  В config.toml укажите:
    mode = "client"
    routing_mode = "socks5"
    server_host = "IP_СЕРВЕРА:8888"
    socks_bind_addr = "127.0.0.1:1080"
2.  Запустите бинарник (права root не нужны):
    ./typroxy
3.  В браузере (через расширения типа FoxyProxy) или в Telegram укажите SOCKS5
    прокси: 127.0.0.1:1080.

🔒 Безопасность

  - Сертификаты генерируются автоматически в памяти на лету.
  - Весь сетевой обмен закрыт шифрованием TLS 1.3.
  - Трафик не содержит сигнатур обычных VPN-протоколов (OpenVPN, WireGuard), что
    защищает от блокировки по эвристике и DPI.
